# 技能体系总览

这一页讲三件事：我的 skill 分哪几类，我做 skill 时反复用的做法，以及全部 skill 的一览。想看某个 skill 为什么这么做，去读它的技能卡。目前写好的技能卡有 9 张，其余 skill 只在下面的一览表里占一行。

## 1. 我的 skill 分哪几类

每张技能卡都写了这个 skill 在我干活的哪一步出场。按这个出场时机归纳，一共 7 类。其中开发相关的几类是顺着一条流程排的：需求 → 设计 → 开发 → 审查 → 构建 → 走查。编排入口负责把这条流程串起来，其余各类各管其中一段，或者管流程之外的事。

| 类 | 干什么 | 有哪几个 |
|---|---|---|
| 编排入口 | 把整条开发流程串起来。三个入口共用同一套阶段和状态，区别在人工门禁有几道 | [auto-task](auto-task.md)、[feature-dev](feature-dev.md)、[bugfix](bugfix.md) |
| 动手前想清楚 | 需求分析、逐轮追问对齐、设计和建模取舍，把要人拍板的问题列出来 | [prd-to-md](prd-to-md.md)、[grilling](grilling.md)、[brainstorming](brainstorming.md)、[product-lens](product-lens.md)、blueprint-first、[to-questionnaire](to-questionnaire.md)、[design-principles](design-principles.md)、database-designer |
| 改完后生效和验证 | 把改动编进开发环境，在浏览器里按角色走查，复杂功能先写测试 | [dev-rebuild](dev-rebuild.md)、[chrome-walkthrough-flow](chrome-walkthrough-flow.md)、tdd、[test-cases](test-cases.md) |
| 出问题时诊断 | 报错或变慢时只读取证，给出原因，不动手修 | [log](log.md)、[perf-diagnose](perf-diagnose.md) |
| 数据库改动落地 | 把开发库上的改动变成能随发版走的脚本；生产订正、种子合并、配置表驱动的组件 | [db-to-dbscript](db-to-dbscript.md)、[prod-data-fix](prod-data-fix.md)、seed-merge、audit-flow-bar |
| 读懂与讲清 | 解读已有模块、画给非技术读者看的图、维护知识库、抓网页和字幕、看公开仓库 | [archify](archify.md)、[biz-tech-brief](biz-tech-brief.md)、[kb-refresh](kb-refresh.md)、llm-wiki、[github-trending](github-trending.md)、baoyu-url-to-markdown、youtube-transcript |
| 管 agent 和会话本身 | 写规则和 skill、换会话交接、复盘、记进度、给循环加上限、找现成的 skill | [agent-craft](agent-craft.md)、[handoff](handoff.md)、[retro](retro.md)、[progress](progress.md)、[loop-engineering](loop-engineering.md)、find-skills |

## 2. 反复出现的做法

下面每一条做法，都在两张以上技能卡的「设计思路」或「换个项目怎么复用」里出现过；只在一张卡里出现的不收。括号里的通行叫法照抄技能卡原文，卡里没标的就不标。

1. **说明文件管判断，脚本管执行。** 模型只决定该不该跑、带什么参数、怎么读结果；机械步骤和格式全交给脚本或生成器。出处：[dev-rebuild](dev-rebuild.md)（「说明文件管判断，脚本管执行」）；[db-to-dbscript](db-to-dbscript.md)（「生成器负责格式，模型负责内容」）。
2. **会变的参数放在方法外面**（配置外置，externalized configuration）。方法写一份通用的；地址、工具路径、账号指针这类值放进每个环境或每个项目各自一份的配置里。出处：[dev-rebuild](dev-rebuild.md)；[chrome-walkthrough-flow](chrome-walkthrough-flow.md)。
3. **把现场信息直接交给 agent，不让它自己去找。** 调用 skill 时自动注入当前配置和未提交的改动；派子代理时把输入输出、范围、红线写成一个上下文包交过去。出处：[dev-rebuild](dev-rebuild.md)（上下文注入，context injection）；[auto-task](auto-task.md)（「子代理不自己找范围」）。
4. **等待、步数、修复环都设上限。** 等待有超时，超时要说清是哪一步没成；步数有上限，连续没进展就跳过，接近上限就收尾出部分报告；唯一的修复环写死次数。出处：[dev-rebuild](dev-rebuild.md)（带超时的等待，timeout）；[chrome-walkthrough-flow](chrome-walkthrough-flow.md)（有界执行）；[auto-task](auto-task.md)（「唯一的修复环写死上限」）。
5. **等真实信号出现再下结论。** 不看端口通没通、页面有没有弹「保存成功」这类表面信号：脚本自己等到出结论；只读操作之后新增的日志；等只有新页面才有的内容出现；数据对不对以查库为准。出处：[dev-rebuild](dev-rebuild.md)（就绪检查，readiness check；按偏移量读日志，log offset）；[chrome-walkthrough-flow](chrome-walkthrough-flow.md)（显式等待，explicit wait；「真值看库，不看页面提示」）。
6. **结果按固定格式交出，没跑完也要交。** 给上层流程用的输出一个固定的结论词，或者一个固定的报告骨架；中途停下也要交出部分结果和原因。出处：[dev-rebuild](dev-rebuild.md)（「全绿」或「未全绿」加原因）；[chrome-walkthrough-flow](chrome-walkthrough-flow.md)（「中途停下也要出部分报告」）。
7. **动手前确认对象是自己的，确认不了就停。** 停进程前核对它确实是自己的实例，不看端口上是谁；写操作只碰这次自己建的数据，分不清是不是自建的就停下。出处：[dev-rebuild](dev-rebuild.md)（进程身份校验）；[chrome-walkthrough-flow](chrome-walkthrough-flow.md)（「分不清是不是自建的就停下」）。
8. **缺的信息不靠猜。** 找不到当前项目的配置就停下让人补，不拿别的项目凑；查不到的列名标「待确认」，没设计的标「待设计」，不凭空造。出处：[chrome-walkthrough-flow](chrome-walkthrough-flow.md)；[prd-to-md](prd-to-md.md)（「不臆造」）。
9. **该人拍板的地方，给选项、推荐和代价，但不替人决定。** 存疑的地方登记成问题，带候选选项和推荐答案；建议必须写清代价；两种说法冲突时并列摆出来，不替我裁决。出处：[prd-to-md](prd-to-md.md)（存疑登记，open questions）；[grilling](grilling.md)（「事实归 agent，决定归人」，每题带推荐答案，选项附风险）；[agent-craft](agent-craft.md)（「代价必填」「冲突并列，不替我裁决」）。
10. **同一份信息只放一处。** 状态只有一个写入口，索引从状态文件重建；已经落盘的东西按位置引用，不抄一份；「做没做完」现场从版本库状态算出来，不另存一份状态。出处：[auto-task](auto-task.md)（单一数据源，single source of truth）；[handoff](handoff.md)（「一处一源」，这一条是上游作者的设计）；[db-to-dbscript](db-to-dbscript.md)（「已完成」从版本库状态现场算出来）。
11. **触发评测正例负例都要有，先跑出红**（触发评测，trigger eval）。每个 skill 配一组用例，有该叫到它的，也有不该叫到它的；相邻几个 skill 放在一簇里测；改描述时用我的真实说法当用例，先让改前的版本跑出红。出处：[dev-rebuild](dev-rebuild.md)；[db-to-dbscript](db-to-dbscript.md)（按簇做）；[prd-to-md](prd-to-md.md)（先红后绿）；[handoff](handoff.md)（先写负例，先红后绿）。
12. **外来 skill 保留上游原样，本地改动能重放。** 有两种做法。一种是正文保留上游原文，本地改动集中、逐条记在来源说明里（供应商化，vendoring）。另一种是改之前把原版整包备份，改完生成补丁，配一个幂等的应用脚本。两种都是为了上游升级后能把本地改动重放回去。出处：[handoff](handoff.md)；[grilling](grilling.md)；[archify](archify.md)（补丁加幂等的应用脚本）。

**相关**：第 1、9 条分别对应协作规矩[能用脚本就用脚本](../10-协作规矩/能用脚本就用脚本.md)和[方案必附风险评估](../10-协作规矩/方案必附风险评估.md)；第 4 条的来历见[循环要有界、有门禁、过程落盘](../50-经验教训/循环要有界、有门禁、过程落盘.md)。

## 3. 全部 skill 一览

「范围」指 skill 是所有项目都能用（全局），还是只装在一个项目里（项目级）。名称、范围、技能卡三栏是用脚本从清单里取的。

| 名称 | 范围 | 一句话用途 | 技能卡 |
|---|---|---|---|
| dev-rebuild | 项目级 | 改完后端代码，只编改动涉及的模块进本机开发环境，重启服务，并自己等到确认能用才报结果 | [有](dev-rebuild.md) |
| chrome-walkthrough-flow | 全局 | 用浏览器按账号和角色把业务系统走一遍，可选走新增到审批的写路径，查库核对后出结构化报告 | [有](chrome-walkthrough-flow.md) |
| archify | 全局 | 把文字需求或 Mermaid 源码画成可交互的单页网页图，自带布局校验；我打了本地补丁让宽图不用删内容 | [有](archify.md) |
| db-to-dbscript | 项目级 | 把开发库上做过的数据库改动打包成格式规范、可重复执行、随发版走的脚本，配收尾提醒防漏补 | [有](db-to-dbscript.md) |
| agent-craft | 全局 | 写规则、写 skill、派子 agent 之前翻的行动卡，每张带建议、代价和出处；附技能库检查和用量统计工具 | [有](agent-craft.md) |
| auto-task | 项目级 | 给一个或一批任务单，主会话当编排器，依次派开发、审查、走查子代理跑完，每步落盘后汇总 | [有](auto-task.md) |
| handoff | 项目级 | 换新会话前把当前会话压成一份交接文档：只写进展、未决和指针，附下个会话该调的 skill | [有](handoff.md) |
| prd-to-md | 项目级 | 需求分析：查清改哪里、能不能做、有什么风险，存疑一律列成带推荐答案的问题交需求方拍板 | [有](prd-to-md.md) |
| grilling | 项目级 | 开工前把方案拆成决策树逐轮追问，每题带推荐答案，事实自己查、决定才问人 | [有](grilling.md) |
| log | 项目级 | 开发环境报错时从服务日志里找到这次报错，给一句话根因、出错位置和修复方向，只读不改 | [有](log.md) |
| prod-data-fix | 项目级 | 按工单生成生产数据订正的一键脚本，分预览、彩排、执行三档，自带备份、行数断言和回滚，交人手动执行 | [有](prod-data-fix.md) |
| bugfix | 项目级 | 缺陷修复全闭环：分诊、定位、只读复现、隔离修复、重建、走查回归、审查，回环次数有上限 | [有](bugfix.md) |
| feature-dev | 项目级 | 没有任务单的单个需求从分析、编码、审查到验证的半自动编排，带两道人工门禁 | [有](feature-dev.md) |
| test-cases | 项目级 | 按需求文档或原型截图生成测试用例，给 agent 走查回归用，可选导出表格给人看；只能手动运行 | [有](test-cases.md) |
| github-trending | 全局 | 用通俗中文讲清一个公开代码仓库是什么、怎么用、值不值得装，也能出热门仓库摘要 | [有](github-trending.md) |
| progress | 全局 | 生成或更新实施进度表并列出各表的下一步；只能手动运行 | [有](progress.md) |
| biz-tech-brief | 全局 | 从业务和技术两个视角讲清一个功能：读懂已有模块或新功能收尾，出 md、网页和三张定稿图，脚本查客观项，只读 | [有](biz-tech-brief.md) |
| perf-diagnose | 项目级 | 页面、查询或定时任务慢时，从前端网络、运行时、后端、数据库四个维度只读取证，给分级优化建议 | [有](perf-diagnose.md) |
| design-principles | 全局 | 软件设计和架构取舍的行动卡：把当前情况对到经典著作的原则，给考虑点、代价和出处，人拍板 | [有](design-principles.md) |
| loop-engineering | 全局 | 把「改到成功为止」的无界重试改成有上限、超限交人、过程落盘的循环，也把反复手动触发的活做成定时任务 | [有](loop-engineering.md) |
| kb-refresh | 项目级 | 从真源单向重新生成项目知识库；只能手动运行 | [有](kb-refresh.md) |
| tdd | 项目级 | 复杂业务功能的测试先行：先列行为切片交人确认，每片先写一条会失败的探针再写刚好让它通过的代码 | 无 |
| seed-merge | 项目级 | 把按模块拆开的种子数据脚本规范化，合并成一份交人手动执行 | 无 |
| audit-flow-bar | 项目级 | 给业务单据的审批状态弹窗加一条由配置表驱动的流程步骤条 | 无 |
| retro | 项目级 | 复盘一次会话，把不超过 5 条改进落到钩子、规范或项目知识里；只能手动运行 | [有](retro.md) |
| to-questionnaire | 项目级 | 把自己拍不了板的问题写成问卷交给别人填；只能手动运行 | [有](to-questionnaire.md) |
| blueprint-first | 全局 | 新功能写代码前分档、反问、出方案和图、讲解，再过一致性检查；只能手动运行 | 无 |
| brainstorming | 全局 | 逐个提问把一个想法理成设计，不出图；只能手动运行 | [有](brainstorming.md) |
| product-lens | 全局 | 开工前用七个问题诊断一个需求值不值得做、为谁做、做到什么程度算成；第三方，原样安装，试点中 | [有](product-lens.md) |
| find-skills | 全局 | 帮着发现和安装现成的 agent skill | 无 |
| database-designer | 全局 | 表结构设计、数据迁移、查询优化、SQL 和 NoSQL 选型、数据建模 | 无 |
| llm-wiki | 全局 | 按 llm-wiki 方法让 AI 持续构建和维护个人知识库，支持网页、PDF、本地文件等多种素材 | 无 |
| youtube-transcript | 全局 | 提取 YouTube 视频的字幕，可带或不带时间戳 | 无 |
| baoyu-url-to-markdown | 全局 | 用浏览器把网页渲染后抓成 Markdown，需要登录的页面可以等人操作完再抓 | 无 |
