# 技能卡索引

一行一张卡。新增技能卡时在这里加一行，不加到[总索引](../INDEX.md)。改某个 skill 时按名字直接读同名的技能卡；想看全部 skill 的分类和反复出现的做法，读[技能体系总览](00-技能体系总览.md)。

- [dev-rebuild 技能卡](dev-rebuild.md) — 改完后端代码一键编译、重启并校验到出结论；含 10 个设计决策、好处的实测数字、换项目可照搬的做法
- [chrome-walkthrough-flow 技能卡](chrome-walkthrough-flow.md) — 用浏览器按角色走查业务系统：方法和项目参数分开、写操作只碰自建单据、查库看真值、有界执行；含 11 个设计决策和踩过的坑（补记无登录应用适配）
- [archify 技能卡](archify.md) — 第三方画图 skill 的用法和我打的本地补丁：列数可配、图框内横滑、跨节点连线绕行，开关缺省关、逐字一致；补丁思路可照搬到别的第三方 skill
- [db-to-dbscript 技能卡](db-to-dbscript.md) — 开发库改完补一份规范、幂等的发版脚本；收尾钩子只提醒不代写、失败放行；数据订正带备份、核验、回滚
- [agent-craft 技能卡](agent-craft.md) — 写规则、写 skill、派子 agent 前翻的行动卡：四段格式代价必填、蒸馏自公开仓库可回查、冲突并列不裁决；附技能库检查和用量去重两件工具
- [auto-task 技能卡](auto-task.md) — 按任务单全自动跑完开发、审查、走查：编排者只派活、隔离换并行、争用点串行、状态单写入口、不能阻断也不许沉默；含 12 个设计决策和「装了没用起来」的局限
- [handoff 技能卡](handoff.md) — 换新会话前写交接文档：上游原有的「只写活的、已有产物按位置引用」，加我改的自动触发和防误触发；附改前改后的触发评测和外来 skill 的供应商化做法
- [prd-to-md 技能卡](prd-to-md.md) — 需求分析：只答改哪里、能不能做、有什么风险，存疑一律登记成带推荐的问题交需求方拍板；含一次「压字数压掉身份」后按真实说法重新定位、评测先见红的经过
- [grilling 技能卡](grilling.md) — 开工前逐轮追问：上游的决策树加前沿、事实自己查决定才问人，加我的用法（先查已有资产、计划模式里问、选项附风险）和什么时候不用；含一次三轮 12 题的例子
- [log 技能卡](log.md) — 开发环境报错首查：先看按日日志、查不到必须回退权威日志，按行号找最近一次、用高信号锚点代替裸 ERROR；报错类请求按动词分流
- [prod-data-fix 技能卡](prod-data-fix.md) — 生产数据订正：先用工单数据分出五类，填空式模板出一键块；预览、彩排、执行三档，行数断言加旧值条件，按业务键现查 ID；只产出不执行
- [bugfix 技能卡](bugfix.md) — 缺陷修复全闭环：编排者只派活，先用探针安全复现，根因过门禁再改，修前红的探针变绿才算回归；回环各限 2 轮，生产报错走如实降级的线上分支
- [feature-dev 技能卡](feature-dev.md) — 单个需求的半自动编排：写码前门禁复述大白话、字段、状态机，每个功能一份设计文档，验证按阶梯走、走查放最后，阻断级问题可豁免但要留理由
- [test-cases 技能卡](test-cases.md) — 按需求生成给 agent 回归用的测试用例：维度逐项过代替条数下限，每条标层级和分组接上测试阶梯，补本项目的高发漏测维度；只能手动运行
- [github-trending 技能卡](github-trending.md) — 讲清一个公开仓库值不值得装：先读 README 原文，固定六段含「什么时候不适合用」，作者的说法转述成「项目自称」；热门摘要用两个角度近似，定时日报因静默空转退役
- [progress 技能卡](progress.md) — 跨会话的实施进度表：文档是唯一真源、网页只由脚本生成，脚本校验「下一步恰好一行」和状态白名单，只凭证据改状态；只能手动运行
- [biz-tech-brief 技能卡](biz-tech-brief.md) — 功能的双读者解读，跨项目通用：上层大白话、下层带代码位置，出 md、网页和三张定稿图，脚本查 8 项客观项、人做读后自测；两个入口（读懂已有模块、新功能收尾），开工先选档位并写明用量；一次完整档 198 万 token 后的降本经过
- [perf-diagnose 技能卡](perf-diagnose.md) — 系统慢的只读诊断：拆成四层，每层写清证实和证伪标准，先查最贵的；结论分主因、放大器、已排除；来自一次查出「网络往返 330ms」的手工诊断
- [design-principles 技能卡](design-principles.md) — 设计取舍时翻的行动卡：书本原则写成触发、建议、代价、出处四段，命中才给一到三张；两层作用域、渐进披露；试点的触发验证没做完
- [loop-engineering 技能卡](loop-engineering.md) — 循环当一等工程构造：四种能力分两个轴，有界、门禁、落盘可审三条宪法，骨架和项目配置分开；按它落地的试点全部退役
- [kb-refresh 技能卡](kb-refresh.md) — 知识库当编译产物：从真源单向、全量、幂等地重新生成，绝不手改；看不见的记忆整段镜像，项目内文档只编目回指；图谱换成零产物的原生关系图；只能手动运行
- [to-questionnaire 技能卡](to-questionnaire.md) — 拍不了板的事写成问卷交给知道的人：只追问「发给谁、要拿回什么」，为异步填写排版；和需求待确认清单划清边界；只能手动运行，在低频观察名单上
- [retro 技能卡](retro.md) — 复盘一次会话，教训改成文件不写总结：七个维度、最多 5 条、按问题性质分流到检查、规范、导航、事实；逐条确认并记账；按自定门槛已该退役
- [brainstorming 技能卡](brainstorming.md) — 第三方头脑风暴 skill 的用法和我的改动：一次一题理成设计、获批前不写代码；改成只能手动、按我的约定落盘不自动提交；全局正文写死了项目约定待清理
- [product-lens 技能卡](product-lens.md) — 第三方产品视角 skill：开工前七问诊断值不值得做；固定提交号原样安装、装前通读，约束写在来源说明里只用三个模式；第一次试点「有条件继续」，主观验收待做
- [agent-browser：从连接浏览器验到真实导出](agent-browser.md) — 插件导出分步核对浏览器身份、界面回显和收件凭据，实测一个插件的单次导出
- [ai-coding-kickoff：按风险选开工深度，从已确认的设计接续](ai-coding-kickoff.md) — 开工技巧：只追问会改变方案的问题，分轻量、标准、深入档，沿用已确认设计，先验最小真实使用路径（草稿，待本人审）
- [jev 技能卡](jev.md) — 第三方判断技能：区分本地预演、宿主模拟和真实服务，保留每层的验证边界（草稿，待本人审）
