# loop-engineering：循环要当成一等工程构造来设计

## 是什么

一套跨项目的方法骨架，管两件事：
- 给「做完要验证、没过要改了再来」的动作加有界的自愈循环；
- 把一次性、靠人反复手动触发的活（日志巡检、知识库重建、摘要和报告）做成定时任务。

上手前先找当前项目的配置文件，拿到构建命令、验证命令、修复用的 agent、版本控制、红线这些值；找不到就停下让我补，不拿别的项目的参数凑。为什么必须有界，经验和事故见[循环要有界、有门禁、过程落盘](../50-经验教训/循环要有界、有门禁、过程落盘.md)；这张卡讲这个 skill 本身怎么设计、落地后怎样了。

## 为什么做它

- **项目里的循环全是写在文字里的。** 2026-07-24 盘点：缺陷修复和需求开发两个编排流程，回退重做没有计数；一个批量工作流的提示词里有一句真正无界的「直到构建成功」。除了一条每日用量报告，没有任何定时自动化；钩子只能事件触发，做不了定时。
- **Claude Code 有了好几种循环能力，各管一摊。** 工作流里的「循环直到」、按间隔重跑的命令、云端定时任务、模型自己排下次唤醒。不先分清楚，就会拿错工具：比如把要读本地库的任务挂到云端定时任务上，结果够不到。

## 设计思路

1. **四种能力分两个轴。** 控制流轴是「一次调用里迭代到条件满足」，用于自愈、收敛；时间轴是「按节拍跨时间反复触发」，用于巡检、定时任务。先判断要的是哪个轴，再选工具。
2. **一条宪法：任何循环都要有界、有门禁、落盘可审。** 有界是写死上限（次数、连续几轮没进展、用量预算）；门禁是到上限或遇到要人决定的事就停下，交一份结构化的「受阻」报告；落盘可审是生成的编排脚本先写到可审的位置，人看过再跑。
3. **三个可复用的模式。**
   - 有界自愈：干活 → 验证 → 没过就只修收敛错 → 回环，到上限停在门禁上；
   - 定时维护：本地资源类的任务用系统定时器加无头命令行，不用云端定时任务；
   - 自进化：定期聚合用量和日志，产出改进建议，交人工采纳，绝不自动改能力。
4. **方法和参数分开**（配置外置，externalized configuration）。说明文件只写骨架；每个项目一份配置，按插槽填。做法照搬浏览器走查那个 skill 的守则。
5. **安全网建在钩子上，不建在权限弹窗上。** 项目有写库拦截、禁止提交、工作流守卫这些钩子时，放宽权限的无头运行仍然安全。
6. **派生物只再生成，不手改。**

## 实现思路

- 组成：
  - 说明文件 98 行；
  - 两份参考：四种能力展开和三个模式的完整配方；七条可迁移的坑；
  - 两个带占位符的模板：有界自愈的工作流骨架、定时任务的包装脚本骨架；
  - 一份项目配置模板，加一个已跑通的项目实例。
- 迁移到新项目：盘点现有循环 → 填项目配置 → 选试点（通常先做编译或测试自愈，收敛条件最干净）→ 套模板，先落盘、人审、再跑 → 跑通后再推广。
- 自进化复盘的提示词定了几条铁律：
  - 每条结论都要引用具体证据，引不出的不写；
  - 现象至少复现两天才进建议；
  - 本周样本少就明说「样本不足」，不凑数；
  - 只写日报单看看不出、聚合后才浮现的结论；
  - 上周的目标逐条核对，连续两周没动的要么重写、要么退役，不无脑结转。

## 关键决策

| 决策点 | 选了什么 | 没选什么 | 为什么 | 依据类型 |
|---|---|---|---|---|
| 循环的底线 | 有界、门禁、落盘可审三条缺一不可 | 失败就重试直到成功 | 无界的文字重试没有计数、没有门禁，改不对会无限花用量；和项目的门禁、先落盘红线冲突 | 评测记录（2026-07-24 盘点）；流程规范 |
| 本地任务怎么定时 | 系统定时器加无头命令行 | 云端定时任务 | 云端够不到本地仓库、本地数据库、会话记录和命令行工具 | 设计文档（2026-07-27） |
| 写型的无头任务谁来建 | 我亲手创建并先验证一次，agent 只写一次性安装脚本 | agent 自己建好挂上 | 安全分类器拦「自动创建可写的无头 Claude」，硬绕会被判恶意 | 事故复盘（2026-07-27、08-03） |
| 自进化的产出 | 只写建议报告，人工采纳 | 自动改 skill 和规则 | 一次周报里价值最高的建议是给开发 agent 预载 3 个 skill，人工审过只预载了 1 个：另两个，一个会反过来调开发 agent 形成循环，一个需要开发 agent 没有的派子代理工具 | 迭代记录（2026-08-04） |
| 方法和参数 | 骨架加每项目一份配置 | 写死一个项目 | 换项目照填插槽；找不到配置就停，不硬套 | 技能说明文件 |
| 描述的边界 | 划清内置的按间隔重跑、云端定时、业务代码里的定时任务 | 什么循环都归它 | 只想按间隔重跑一句提示时用内置命令就够；业务定时任务是普通编程 | 迭代记录（2026-11-03，426 字压到 286 字） |

「依据类型」只说明这条决策是凭什么定的。对应的原始材料不随本库提供，读这张卡不需要去找它们。

## 怎么用

- 我会说：「把这个自愈循环改成有上限」「编译失败自动修直到通过」「每天定时用 Claude 分析会话」「每周做一次自进化复盘」。
- 不用它：只想按固定间隔重跑一句提示（用内置命令）；云端定时（用云端定时任务）；业务代码里的定时任务。

## 好处

| 同一件事 | 没有它 | 有了它 | 依据 |
|---|---|---|---|
| 编排流程的回环 | 没有计数 | 缺陷修复、需求开发的回环都改成最多 2 轮，超限交人 | 实测，迭代记录（2026-10-28）。是按这条宪法改的，不是调用这个 skill 改的 |
| 定时任务里用数据库 MCP | 无头运行时 MCP 一直连不上 | 包装脚本里把 Node 加进 PATH 后，干净环境下探针返回正常 | 实测，事故复盘（2026-07-27） |
| 把整套自进化做成可迁移的套件 | 只能在本机用 | 改几条路径、跑一个安装脚本，就能装好每日和每周两个引擎 | 设计意图，未实测。没有在另一台机器上装过 |

## 代价与局限

- **按它落地的试点全部退役了。** 2026-11-04 清点：
  - 有界编译自愈循环从未运行；
  - 每周自进化复盘的定时任务改成了手动触发的复盘命令；
  - 7×24 常驻的 agent 分身，8 月以来只完成 1 个任务；
  - 每日热门仓库摘要静默空转 62 天后退役；
  - 每日用量报告，2026-11-09 我判断没起作用，也暂停了。

  现在本机没有在运行的定时任务。
- **skill 本身一次没被调用过。** 宪法被吸收进了各编排流程和规则文件，这个 skill 反倒用不上。
- **写型无头任务的创建绕不开人。** 每次都要我亲手跑安装脚本。

## 踩过的坑

七条可迁移的坑都在它的参考里。下面几条是落地时真踩到的：
1. **定时任务的环境里没有 Node。** 经 Node 启动的 MCP 永远「正在连接」。
2. **定时任务跳过却正常退出。** 静默空转 62 天没人发现。
3. **安全分类器拦写型无头任务。** 只读的探针放行，写型的整条被拒；后来改成 agent 写一次性安装脚本、我来跑。
4. **定时要避开已有任务。** 已有报告的定时写的是 8 点，文件却在 23 点被另一个来源重新生成过，新任务两个时间都避开。

## 换个项目怎么复用

可以照搬的做法：

- 先分轴：要的是「一次调用里迭代」还是「跨时间反复触发」。
- 有界、门禁、落盘可审三条写进模板，不靠提示词自觉。
- 修复 agent 只修收敛错，遇到设计决策就标「需要人」停下。
- 本地资源类任务用系统定时器，不用云端定时任务；包装脚本要能在最小环境里跑。
- 自进化只产建议，证据绑定、样本诚实、目标两周不动就重写或退役。
- 骨架和项目配置分开，找不到配置就停。
- 上线前先写好「没人用就退役」的条件，到点清点。

要按项目重写的：项目配置里的构建和验证命令、修复用的 agent、调度器、候选任务、红线。
