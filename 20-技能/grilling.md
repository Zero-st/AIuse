# grilling：开工前逐轮追问，把决定问清

## 是什么

我要做一个新东西、自己又没想清楚时，让 agent 当面试官：把方案拆成一棵决策树，每轮问一批题，每题带它的推荐答案，我答完它再算下一轮，直到所有分支都问过、没有默认的假设。说明文件除了描述和末尾一节，全是上游原文。

## 为什么做它

- **为什么装。** 评估那个公开仓库时，我挑了 4 个和项目栈无关的 skill 装进项目，它是其中之一（2026-10-20）。
- **它补的是什么。** 我已有的规矩是「先计划、只问一轮」。可是做一个会长期用的东西时，决定之间互相牵制，一轮问不完；不问清就动手，返工的是整套结构（推测，材料里没有直接写这条动机）。
- **本地为什么还要改。** 项目里业务叫法和表、字段、角色编号常常对不上。追问时顺带确认下来的术语，值得留下来，不让下一次再解释一遍。

## 设计思路

上游原有的设计（不是我定的）：

1. **决策树加「前沿」。** 每个决定下面挂着依赖它的决定。「前沿」是前提都已定下的那些决定，也就是现在就能问、不用猜答案的题。
2. **按轮问。** 一轮把整个前沿问完，题目编号、每题带推荐答案，措辞让「是」就等于接受推荐，可以按编号一口气答。依赖本轮另一道题的，放到下一轮。上游文档说，十三道题通常三轮左右就问完。
3. **事实归 agent，决定归人。** 能从环境里查到的事实，派子代理去查，不来问人；查的过程中只有依赖这个事实的题等着，其余照问。决定一律交给人，agent 自己替人答就算跑坏了。
4. **问完等确认再动手。** 前沿空了还不算结束，要我确认「理解一致」才算。

本地加的：

5. **术语回写。** 对齐中确认了某个业务词的含义，收尾时问我一句，同意后写进项目的术语表；已有同义词条就改那一条，不并排新增。

我的用法（来自一次实际使用）：

6. **开问前先查已有资产。** 先把相关的规则、记忆、skill、笔记摸一遍，第一轮才问得准。
7. **放在计划模式里做。** 追问期间 agent 只读不写，问完直接把答案落成计划，带验收标准和第一个样品。

## 实现思路

- 组成：一份说明文件 34 行，一份来源说明（上游地址、版本、许可全文、本地改动、升级步骤）。没有脚本。能自动触发，也能用斜杠命令。
- 一次运行：拆树 → 算前沿 → 发一轮 → 等我答 → 重算前沿 → 下一轮 → 前沿空了等我确认 → 问我要不要回写术语。
- 我实际用时，每轮通过提问工具发，一轮最多四题，每个选项按我的规矩附上风险。
- 升级方式：拉上游同一路径的文件比对，再重放本地改动（供应商化，vendoring）。

## 关键决策

只列我自己做的决定；上游的设计见上一节。

| 决策点 | 选了什么 | 没选什么 | 为什么 | 依据类型 |
|---|---|---|---|---|
| 怎么装 | 从那个仓库单独挑出来装到项目级，保留自动触发 | 整包装成插件 | 那个仓库的工程类 skill 大多绑 git、代码托管平台的 issue 和特定测试栈，和本项目对不上 | 设计文档（2026-10-20 安装计划） |
| 上游的别名 skill | 删掉，并入它 | 跟上游一样留着 | 斜杠命令本身就能手动调它，别名零增益；升级时也不用再重放 | 迭代记录（2026-10-28） |
| 要不要挪到全局 | 留在项目级 | 挪到全局，所有项目共用 | 要给它加只适用于本项目的术语回写 | 设计文档（2026-11 技能库分层优化，列为不做） |
| 和相邻追问类 skill 怎么分 | 描述里划界：创意发散、完整规划出图、交给别人填的问卷各归别的 skill | 把三套追问纪律合并成一套 | 那两个相邻的 skill 已经改成只能手动，不会和它抢触发 | 设计文档（2026-11 技能库分层优化，列为不做） |
| 描述写多长 | 从约 350 字压到约 230 字，开头写清方法，加中文触发词 | 保留上游的一句英文 | 项目给能自动触发的 skill 定了 300 字预算 | 迭代记录（2026-11-03）；评测记录 |
| 术语回写 | 文末加一节，收尾问我一句再写进术语表 | 不回写 | 业务叫法和表、字段、角色编号对不上的词，说错了会写错代码 | 设计文档（2026-11 技能库分层优化）；迭代记录（2026-11-04） |
| 每轮怎么发 | 用提问工具，一轮最多四题，每个选项附风险 | 上游的纯文本格式，整个前沿一次问完 | 风险是我对所有选项的规矩；四题是提问工具本身的上限（2026-11-24 核对：一次 1～4 题） | 真实运行（2026-11-23）；本人要求（选项附风险）；实现代码（提问工具的参数定义，2026-11-24 核对） |
| 在什么模式下问 | 计划模式：只读，问完落成计划，带验收标准和第一个样品 | 问完直接动手 | 上游也提醒过，模型问完容易直接开工，跳过确认这一步；计划模式天然有这道门 | 真实运行（2026-11-23）；本人要求 |
| 什么时候不用 | 要铺开到很多对象、我还没见过样品时，问一轮就写计划、先做一个样品 | 照样多轮追问 | 范围和档位要看了样品才定得下来 | 本人要求 |

「依据类型」只说明这条决策是凭什么定的。对应的原始材料不随本库提供，读这张卡不需要去找它们。

## 怎么用

- 我会说：「拷问我一下这个方案」「把这个想法问透」「开工前一题一题和我对齐」。
- 什么时候用：新建一个会长期用的东西；方案分支多、各分支互相牵制。
- 什么时候不用：
  - 要铺开到很多对象、而我还没见过样品时。问一轮就写计划、做一个样品，范围和档位看了样品再定，见[先计划再做最小样品](../10-协作规矩/先计划再做最小样品.md)。
  - 装软件这类有合理默认值的小任务，见[装软件类任务不要提问打断](../10-协作规矩/装软件类任务不要提问打断.md)。
  - 创意发散、完整规划出图、要把问题交给别人填，各有别的 skill。

## 例子：一次三轮追问

2026-11-23 搭这个资料库时，三轮 12 题定完了全部决定。开问之前 agent 先查出我已有四处相关资产：全局规则 46 行、记忆 127 条、skill 34 个、一个 343 篇的笔记库。第一轮的问题因此从「你想要什么」变成了「新库和现有这些怎么分工」。不先查事实，这一轮问不出来。

| 轮次 | 定了什么 |
|---|---|
| 第一轮：定位 | 谁来读、和已有笔记库的关系、和正在生效的规则的关系、先接哪个 agent |
| 第二轮：内容 | 收哪些、副本怎么生成、目录怎么分、新内容怎么进来 |
| 第三轮：接线 | 入口怎么接、和记忆怎么分工、技能目录怎么填、要不要版本管理 |

## 好处

下表的「它」指上游的追问方法加上我的用法；术语回写是本地加的。

| 同一件事 | 没有它 | 有了它 | 依据 |
|---|---|---|---|
| 定完一个新东西的全部决定 | 边做边问，或者一轮问不全 | 三轮 12 题定完 | 实测。真实运行（2026-11-23，只有一次） |
| 第一轮问得准不准 | 开口就问「你想要什么」 | 先查出已有资产，第一轮直接问「和现有这些怎么分工」 | 实测。真实运行（同一次） |
| 我说「拷问我一下」时它出不出场 | 无从比较 | 两条正例改描述前后都命中，同簇 10 条用例 10/10 → 10/10 | 实测。评测记录（2026-11-03 簇评测，作回归护栏） |
| 业务术语对不上 | 每次重新解释 | 确认过的术语进术语表 | 设计意图，未实测 |

## 代价与局限

- **只用过一次。** 2026-11-23 的一份复评统计时它是零调用，建议这一簇只留创意发散那个 skill，其余提删除，还没定。
- **术语回写没有产出。** 同一份复评里术语表新增 0 条，没到预设的 5 条门槛；按原设计，术语表要退回记忆里管。
- **轮的边界靠模型判断。** 上游文档承认，前沿不是从图里算出来的，可能把互相依赖的两题放进同一轮。只能我指出来，下一轮重开那个分支。
- **弱一点的模型会问两三题就开工。** 上游文档说，低档或非前沿模型常把「问到理解一致」压成几个问题加一份大纲。靠确认这一步，以及一句「没允许不要动手」。
- **推荐答案有时和题目措辞方向相反。** 这时同意推荐等于答「否」，要直接回应推荐并说明。
- **不设题数上限，是上游有意的。** 问得太久，多半是范围太大，拆开分别问。
- **和「只问一轮」的规矩有张力。** 所以「什么时候不用」要说清，不能见方案就拷问。

## 踩过的坑

1. **项目能力索引写错了触发方式。** 曾写它「手动调用」，实际能自动触发；第一次改成「也可斜杠手动」又被技能库检查脚本的关键词窗口误判，最后改成「也支持斜杠命令」。
2. **上游的别名是零增益。** 上游另有一个只转调它、只能手动的别名 skill，跟着一起装了进来。后来发现斜杠命令直接调它就行，2026-10-28 删掉别名；全局速查表里留着的那一行，到 11-03 才顺手去掉。

## 换个项目怎么复用

可以照搬的做法：

- 决策树加前沿、按轮问，依赖未答题的放下一轮（上游）。
- 事实自己查、决定才问人；查事实时不阻塞别的题（上游）。
- 每题带推荐答案，措辞让「是」等于接受推荐（上游）。
- 问完等人确认再动手（上游）。
- 开问前先查已有资产；放进计划模式，问完落成计划和第一个样品；选项附风险，见[方案必附风险评估](../10-协作规矩/方案必附风险评估.md)。
- 外来 skill 用供应商化（vendoring）的办法维护，做法同 [handoff 技能卡](handoff.md)。

要按项目重写的：术语表放哪、长什么样；和相邻 skill 的划界；提问工具一轮能发几题。
