# chrome-walkthrough-flow：按角色把业务系统在浏览器里走一遍

## 是什么

用 Chrome 开发者工具的 MCP 接口（chrome-devtools MCP）驱动浏览器，把业务系统按「账号 × 角色」走一遍：登录 → 切角色 → 逐页看快照、控制台报错和失败的网络请求 →（写模式下）新增、提交、切角色审核 → 用只读查询核对数据库 → 出报告和问题清单。它在「代码改完、服务重启之后」出场做端到端验证，也被缺陷修复流程拿去做只读复现和回归。

## 为什么做它

- **步骤和坑每次现找。** 登录表单、切角色的地址、验证码怎么办、审核确认弹窗怎么过，每次都要重新摸。早期一次用量画像（2026-08）：浏览器工具真实调用 898 次，集中在 17 个会话，最高频的业务动作是切角色（41 次）。
- **方法和参数绑在一起，换项目就套错。** 早期版本把一个项目的地址、账号、数据库写死在方法里；整理进公开仓库时，发现快照里混进了另一个项目的内网数据库地址。
- **共享环境上的写操作不可逆。** 开发环境多人共用，走查时用同一个管理员账号切各种角色；误审、误退、误删别人的单据，事后补不回来。
- **工具本身会卡死。** 带后台轮询的单页应用网络永远不空闲，新开页面或刷新会一直等到超时。

## 设计思路

1. **方法和参数分开**（配置外置，externalized configuration）。说明文件只写通用方法；地址、登录方式、切角色方式、数据库通道、落盘目录、步数预算全放在每个项目一份的配置里。找不到当前项目的配置就停下让人补，不拿别的项目凑。
2. **两种模式，写只碰自建单据。** 只读走查只看、只点导航、只查库；写路径端到端可以新增、提交、审核、退回、删除，但只作用于这次自己建的测试单据。分不清是不是自建的就停下。
3. **真值看库，不看页面提示。** 页面上的「保存成功」只是提示，落库和状态流转对不对以只读查询为准。
4. **有界执行。** 步数有上限，同一操作连续没进展就记「受阻」跳过；接近上限就收敛、出部分报告，不空转。
5. **等目标出现，不睡固定时长**（显式等待，explicit wait）。快照和断言前先等一段只有新页面才有的文字；切角色后先等再验证。
6. **报告结构固定。** 按角色、页面分组，问题分四级，每条带可定位信息（地址、菜单路径、报错原文、请求和状态码）；中途停下也要出部分报告。

## 实现思路

组成：

- 说明文件 81 行：选配置的协议、通用方法 7 步、硬规则、报告骨架。全部由模型执行，没有脚本。
- 项目配置模板 63 行：每个插槽带填写说明，末尾附「填完后搜占位符应零残留」的自检。目前两个项目各有一份配置。
- 工具坑参考 28 行：单页应用怎么驱动、共享机只动自己的进程、不按命令行模式批量结束进程。
- 配套一个限权的走查子代理：只授予交互、巡检、弹窗类工具，故意不给性能剖析和设备模拟类。开发编排流程串行派它；缺陷修复流程用只读模式派它做复现和回归。
- 账号放在项目里一个不进版本库的文件，配置里只写指针。

一次运行的顺序：选配置 → 读账号（不存在或还是占位符就停，不编账号）→ 登录（出现验证码就停下请人，不自动识别）→ 定范围（调用方给了清单就照单走，没给就按账号 × 角色遍历首屏，范围大先确认优先级）→ 切角色（从页面下拉读出角色和 ID 再切，记进报告）→ 逐页：快照、控制台、网络 →（写模式）按主链路走，每个状态切换点查库 → 出报告。

## 怎么用

- 我会说：「走查一下这个模块」「用浏览器走一遍，切角色测审核」「端到端联调一下」。要进开发环境看页面时也先加载它，照配置里的入口走。编排流程走到「走查」这一步时派走查子代理，子代理预载它。
- 输入：要走的范围（清单或模块名），模式（不说就按配置的默认）。输出：结构化报告和问题清单；给了任务目录就落盘。
- 不用它：只想把网页抓成文档（交给网页转文档的 skill）；性能剖析（交给性能诊断的 skill）；改了后端代码、服务还没重启（先交给重启的 skill，否则走查打到旧代码）。

## 代价与局限

- **护栏全靠提示词。** 浏览器工具没有任何拦截钩子，「只碰自建单据」「不超过 40 步」都靠模型自觉；只有数据库的写操作有钩子拦。
- **子代理那条路没完全兑现。** 2026-08 的用量画像里，浏览器操作 76% 是主会话直接驱动，子代理只占 24%；当时还记下过「子代理驱动浏览器会空转」。之后没有重新统计。
- **全靠模型执行。** 没有脚本，步数多、上下文涨得快。范围大时要先排优先级，40 步走不完。
- **直接调页面函数很脆。** 绕过了语义点击，页面结构一变就失效。

## 踩过的坑

1. **绕开分流。** 同一个域名后面挂着好几个开发者的实例，靠一个分流标记把请求打到自己的实例；直连端口或忘设标记，看到的就不是本次改动。
2. **语义点击点不动。** 链接地址是占位符、动作挂在点击事件上的元素，无障碍点击常不触发；读出点击事件里的业务函数直接调。
3. **原生确认框被延迟。** 自动化下确认框被异步处理，页面的确认分支提前中止，请求根本没发出去。先预置自动接受再触发。
4. **改写确认函数被拦。** 想一劳永逸地把页面确认函数改成恒真，被安全分类器拦下。
5. **审核权限。** 自己提交的单据自己审不了，要换账号；部门级审核按提交人所在部门隔离，审核账号得和提交账号属于同一部门，否则待审列表里根本看不到。
6. **共享机上别人的进程。** 机器上同时跑着别人的调试浏览器和工具进程，按名字一查上百个，只处理自己用户名下的；按命令行模式批量结束进程会连自己的 shell 一起杀掉。
7. **后台标签截不了图。** 后台打开的标签不渲染，截图超时；要截图只能切到前台，会打断正在看页面的人，先问再切。

## 换个项目怎么复用

可以照搬的做法：

- 方法和参数分开（配置外置，externalized configuration）；配置模板带插槽说明和「零占位符残留」自检；找不到配置就停。
- 两种模式（只读、写路径），写操作的作用域限定为本次自建的数据，分不清就停。
- 真值以数据库查询为准，不看页面提示。
- 显式等待（explicit wait），不用固定睡眠。
- 有界执行：步数上限、连续无进展就跳过、到点出部分报告。
- 固定的报告骨架：按角色分组、问题分级、每条带可定位信息。
- 账号放不进版本库的文件，报告脱敏；角色 ID 运行时取，不写死。
- 限权子代理：只授予走查需要的工具子集。

要按项目重写的：登录方式和表单字段、切角色方式、实例分流方式、数据库通道、审核链和禁止自审的规则、落盘目录、步数预算。

## 补记：无登录应用的项目适配

走查配置可以只保留与业务有关的场景。一个单人本地网页应用没有登录、角色或数据库，适配在配置中给出真实后端入口、当前活动视图和具体写入禁区。2026-10-28 退役一组功能后，视图由源码核对，走查只覆盖三个保留页面及其受影响状态。测试查看主题、历史切换、网络、控制台和停后端重载，避开采集、模型和真实内容写入。

同一轮走查发现页面漏引用共享数据及遗留弹窗，修正后复验。配置更新来源于实际范围变化。历史记录足以确认这轮走查和适配，未给出技能独立调用次数，原卡的跨项目统计口径保持。换项目重查入口、当前视图、允许交互、数据核对方式和是否有离线承诺。
