# kb-refresh：知识库是编译产物，从真源重新生成

## 是什么

项目知识库的生产端。我敲命令，它按一份清单配置做六步：
1. 读清单；
2. 把项目外的记忆整段镜像进来，项目内的文档只编目、不拷贝；
3. 用数据库只读工具抽取存储过程和配置表；
4. 交给公开的知识库 skill 重建页面、索引和别名词表；
5. 写一行日志；
6. 打印待提交清单交给我。

人用笔记软件或 grep 看，Claude 用知识库 skill 查，两边同一个入口。

## 为什么做它

- **知识不缺，是散，而且最值钱的一部分人看不见。** 2026-07 盘点有五类载体：项目里的文档、Claude 的记忆、代码、数据库、版本库日志。其中记忆有 32 条，记着数据溯源、状态机、角色权限、踩坑结论，只有 Claude 看得见：藏在隐藏目录里，没有搜索界面，也不在项目树里。数据库里的存储过程和配置表驱动的逻辑，grep 代码看不到。
- **一个真实问题要横跨五处手工拼。** 比如「这笔金额从哪来、改它要动哪几份映射副本、以前踩过什么坑」，要在记忆、需求文档、事实清单、代码、数据库之间来回找。
- **知识库一旦能手改，就会和真源分叉。** 所以生产端要单独做成一个「从真源重新生成」的步骤。

## 设计思路

1. **单向再生成**（一处一源）。真源不变，知识库是编译产物；一条命令全量重跑。要改内容就改真源，绝不手改知识库页面。
2. **混合架构。** 公开的知识库 skill 管存储、组织和检索；自建这个 skill 管「真源编译」这一层。
3. **引用而非复述，按源区别对待。** 项目内的文档只编目、页面里回指原文，不拷贝；只有项目外的记忆整段镜像进来，因为它在项目树里看不到。
4. **幂等。** 记忆按内容摘要增量镜像；页面生成前先查缓存，命中就跳过；真源没变时再跑，零差异。
5. **确定性成页。** 设计文档类的来源必定成一页，不靠模型判断「值不值得」，免得漏页。
6. **抽不到不中断。** 数据库对象抽不到或已失效，记日志、页面标「未验证」，其余步骤照常。

## 实现思路

- 组成：
  - 说明文件 114 行，按步骤写，固定路径和红线每次照抄；
  - 一个编目脚本：镜像记忆、编目项目内文档，幂等；
  - 一份清单配置，是唯一的配置：来源清单、要抽的数据库对象、红线。
  - 消费端用公开的知识库 skill 查询，加笔记软件的原生关系图。
- 分工：镜像、编目、缓存判断交给脚本；读原文、写摘要页和实体页、维护索引留给模型。
- 红线：数据库只读；只写知识库自己的目录；不提交，打印清单交给我；中间文件不进系统临时目录。

## 怎么用

- 我会敲：命令本身，不带参数。改了记忆、文档或数据库配置之后跑一次。
- 不用它：只是查知识（用知识库 skill 查询，或者直接 grep）；想改某一页（改它的真源）。

## 代价与局限

- **几乎没再跑过。** 近 400 天通过 skill 调用 0 次。只能手动，就要靠我想起来；我改了真源却不跑，知识库就过期。
- **覆盖不全。** 业务地图和深挖文档没有逐篇成页，靠主题页回指原文覆盖。
- **定时重建一直没启用。** 无头运行要写文件，被分类器拦下，命令留在设计文档里等我亲手启用。
- **每周巡园是空转。** 原来每周有一段只读脚本扫稀疏页和孤儿页，连续 13 周的报告正文一模一样，没人看，2026-11-04 随那条定时任务一起停了。
- **页面里回指原文的相对路径曾经差一层。** 已有的页要改生成规则后全量再生成才能修。

## 踩过的坑

1. **文件名后缀决定被归到哪一类。** 清单按后缀把「设计文档」归一类，别的文档用了同样的后缀，就会被归错，还会被强制套上设计模板。所以解读类文档绝不用那个后缀，见 [biz-tech-brief 技能卡](biz-tech-brief.md)。
2. **补丁摞补丁就该换方案。** 离线图谱为了绕开工具版本和死重的前端库叠了两层补丁，最后整体删掉，换成零产物的原生关系图。
3. **数据库抽取要限定所有者。** 数据库是多个租户共用的，不限定所有者就会抽到别的租户的对象。
4. **生成的文件要我手工提交。** 缓存文件不该提交，要加进忽略列表。

## 换个项目怎么复用

可以照搬的做法：

- 一处一源：知识库当编译产物，单向再生成，禁止手改，要改就改真源。
- 项目外看不见的知识整段镜像进来；项目内的只编目、回指原文。
- 幂等：按内容摘要增量，缓存命中就跳过，真源不变就零差异。
- 某类来源确定性成页，不靠模型判断值不值得。
- 抽取失败不中断，标「未验证」。
- 存储检索用现成的，自建只做编译层。
- 写文件的批量任务设成只能手动，产物交人提交。

要按项目重写的：真源有哪几类、清单配置、数据库抽取对象、知识库的目录结构。
