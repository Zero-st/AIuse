# github-trending：讲清一个公开仓库，值不值得装

## 是什么

两件事。一是讲仓库：我贴一个链接或仓库名，它先抓真正的 README，再按固定六段讲：一句话概括、解决什么问题、怎么工作的、应用场景、什么时候不适合用、怎么用。二是热门摘要：用代码托管平台的命令行工具，从两个角度近似「热门」，出一份一行一个仓库的清单。我看到一个仓库、想知道要不要装时用它。

## 为什么做它

- **平台没有公开的「热门」接口。** 想定期看新出的好项目，只能用搜索接口近似。
- **只看一行简介判断不了要不要装。** 清单里的简介是平台的元数据，常常过时、含糊，或者只是把仓库名重说一遍。要讲清一个仓库，得读它的 README，而且讲法要固定，不然每次详略不一、术语成堆。
- **我真正的用法是「讲仓库」。** 2026-11-03 跨项目扫会话记录：它只被自然叫到 1 次；我的真实说法是「（链接）看这个仓库，哪些 skill 适合装」，半年里一次也没说过「热门」。

## 设计思路

1. **两个角度近似热门。** 一是最近几天新建、按星数排的（新晋）；二是最近几天有提交、星数过门槛的（活跃）。两个一起看，回答的是「新冒出来的」和「本来就大、现在还活跃的」两种不同问题。
2. **讲仓库用固定六段，不即兴发挥。** 六段一个不少；README 里确实没有的才跳过，不硬凑。「什么时候不适合用」必须写，不只讲好处；README 自己写了不做什么的，直接用。
3. **读原文，不猜。** 先抓 README；中文提问时优先中文版 README。猜一两次路径还 404 就别再猜了，回去读英文版，找开头的语言切换链接。
4. **保持怀疑。** README 是作者自己的宣传，星数衡量的是关注度，不是正确性或成熟度。没法复现的夸张说法，转述成「项目自称」，不变成自己的结论。新晋那一类尤其多这种噪声。
5. **只读，权限最小。** 只调只读的搜索接口；发现命令行工具的令牌带写权限，提醒一句换成只读的，不反复唠叨。
6. **只讲到 README 这一层。** 作者的设计思路、取舍的蒸馏不归它；那个 skill 已经退役。

## 实现思路

- 组成：说明文件 220 行；一个搜索脚本，参数有回看天数、条数、星数门槛、附加限定条件、多个主题按「或」组合。
- 热门摘要：先查命令行工具在不在、登没登录，不假设；按我的说法换算参数，比如「Python 的」换成语言限定，「AI 项目」没有单一的主题标签，就用几个主题按「或」组合；冷门方向把星数门槛调低。脚本跑两个角度，模型去重、排版。
- 讲仓库：抓 README → 按六段写 → 夸张说法标「项目自称」。
- 分工：搜索、拼查询交给脚本；判断主题怎么映射、讲解和怀疑留给模型。

## 怎么用

- 我会说：「（链接）这个项目是干嘛的，通俗讲讲」「看这个仓库，有哪些 skill 适合装」「最近有什么火的仓库」。
- 不用它：要蒸馏作者的设计取舍；要读源码细节、问题单、合并请求。

## 好处

| 同一件事 | 没有它 | 有了它 | 依据 |
|---|---|---|---|
| 讲一个仓库给不懂技术的人 | 每次详略不一，容易只讲好处 | 固定六段，「什么时候不适合用」必写 | 设计意图，未实测。没有前后对照 |
| 拼一份「给小白讲仓库」的提示词 | 从零写 | 2026-09-23 在另一个项目里，把它的六段模板和另外几份清单合成一套九问模板，用全新子代理原样跑，三条自检全过 | 实测，真实运行（2026-09-23，1 次）。那次跑的是合成后的提示词，不是它本身 |
| 定期看热门 | 手动搜 | 每天定时出摘要 | 实测后已退役：挂上后从第 38 天起就静默跳过，空转 62 天没人发现 |

## 代价与局限

- **热门摘要这半基本没人用。** 我半年没说过「热门」；定时日报 2026-11-04 退役。
- **只到 README 这一层。** README 写得差的仓库，只能再翻几个源文件补，讲出来也有限。
- **依赖命令行工具已登录。** 没登录就什么都出不来；定时任务正是死在这上面。
- **说明文件是英文为主。** 输出模板是中文，正文说明是英文，读和改都要切换。

## 踩过的坑

1. **定时任务跳过却正常退出。** 从 2026-09-03 起命令行工具一直没登录，脚本每天记一行「跳过」然后正常退出，摘要停在 9 月 3 日，62 天后清点才发现。教训见[循环要有界、有门禁、过程落盘](../50-经验教训/循环要有界、有门禁、过程落盘.md)。
2. **自动模式不让 agent 改定时任务表。** 退役时那一行要我在命令行里亲手删，见[自动模式的分类器会拦什么](../50-经验教训/自动模式的分类器会拦什么.md)。
3. **同名不同义。** 另一个知识库的配置目录里已经有一个同名、做别的事的 skill，所以迁移时没放进那个目录，换了一个位置。
4. **中文 README 的路径五花八门。** 一直猜文件名很浪费，读英文版找语言切换链接最快。

## 换个项目怎么复用

可以照搬的做法：

- 平台没有现成接口时，从两个互补的角度近似（新晋加活跃）。
- 讲一个外部工具用固定结构，「什么时候不适合用」必写。
- 读原文不读元数据；作者的说法转述成「项目自称」。
- 只读、最小权限的令牌，发现权限过大提醒一次。
- 描述以我真实的说法为锚，不以功能名为锚。
- 定时任务跳过要非零退出，或者进日报统计。

要按项目重写的：搜索角度和门槛、主题映射表、输出模板的语言。
