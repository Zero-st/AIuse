# perf-diagnose：系统慢，四层交叉取证找主因

## 是什么

我说「整站好卡」「点查询要等十几秒」「定时任务老超时」时出场：
- 先跑一个采集脚本，收机器侧的证据：进程、数据库连通和往返、运行时参数、垃圾回收和堆、线程、日志错误计数、系统负载；
- 再用数据库 MCP 量往返延迟；
- 委派走查 agent 在浏览器里测首字节时间；
- 最后写一份报告：现象、四层证据、主因加放大器加已排除、分级优化建议。

全程只读。

## 为什么做它

- **整站慢要反复诊断，每次临场手敲。** 2026-08-26 第一次查「整个系统响应很慢」，靠手工一项项试，容易漏一层，也没法复用。
- **那次查出来的主因出乎意料。** 不是代码、不是垃圾回收、不是数据库内部，是开发机到数据库的网络：每趟往返约 330ms，正常内网应该不到 1ms。一页几十条串行 SQL，首页首字节等 12 秒，一个列表页 25.7 秒；一个只返回 12 个字节的接口也要等 8～13 秒。
- **共享机上容易查错进程。** 机器 128 核、跑着大量别人的 Java 进程。第一轮按进程名找，把别人进程的堆大小和回收器参数当成了自己实例的。

## 设计思路

1. **四层互斥，各自可证实、可证伪。** 每层写清「判定就是它」和「判定排除」的标准：
   - 数据库与网络：热连接上一条空查询就要几百毫秒，就是它；网络往返小于 5ms、空查询小于 20ms，排除；
   - 运行时与垃圾回收：老年代居高不下、完整回收次数持续上涨，就是它；
   - 后端应用：小响应、长首字节时间，再伴随多趟数据库往返；
   - 前端：慢在下载是包大或没压缩，慢在首字节就回到后端和数据库。
2. **先打最贵、最常见的假设。** 数据库和网络排在第一个查。
3. **几句判读口诀。**
   - 12 个字节的响应等十几秒，一定是服务端多趟数据库往返，不可能是传输慢；
   - 数据库那头零耗时的空查询也慢，说明是网络，不是数据库内部；
   - 垃圾回收健康、系统负载远低于核数、内存富余，就排除运行时和机器。
4. **只诊断，不落地。** 不结束进程、不重启、不改配置、不写库。优化建议写进报告，由人按流程落地：改配置交给编译重启的 skill 验，建索引交给发版脚本的 skill。
5. **结论分三档。** 主因、放大器、已排除，每条都带证据引用，不只给一个「可能是」。

## 实现思路

- 组成：
  - 说明文件 78 行；
  - 一个采集脚本，分七节输出，最后打印小结；
  - 一份设计文档；
  - 说明文件用工具白名单限定：只能跑采集脚本、只读的看日志命令和数据库只读查询。
- 分三路取证：
  - 机器侧交给脚本；
  - 数据库往返由主会话用 MCP 连发几条空查询，记每次的执行时间：冷连接含握手，会大很多；热连接约等于一次往返；
  - 前端首字节时间委派走查 agent，只测量不写数据。环境里常常没有性能剖析工具，就用浏览器自带的导航计时接口代替。
- 分工：采集交给脚本和工具；四层判读、主因和放大器的取舍留给模型。

## 怎么用

- 我会说：「点击查询响应很慢，排查一下」「这个页面要等十几秒」「整站好卡」「定时任务老是超时」。
- 不用它：看某条报错（交给日志首查）；要修 bug（交给缺陷修复）；Claude 的工具或浏览器自己卡住了（不是系统性能问题）。

## 代价与局限

- **一次都没通过 skill 用过。** 设计文档里的「端到端复跑一次，独立复现主因」一直没做。
- **没有并发时看不出线程卡在哪。** 没人用的时候，处理请求的线程大多空闲；「请求卡在数据库」要有负载时复采才明显。
- **访问日志没有耗时列。** 拿不到服务端每个请求的耗时，只好让浏览器补测首字节时间。要不要改日志格式是配置改动，没定。
- **环境事实写死了。** 端口、实例目录、工具路径、日志位置都是这一台开发机的。

## 踩过的坑

1. **按进程名找进程，读到了别人的。** 共享机上一定要按监听端口定位。
2. **挂着调试器的进程，有些诊断工具用不了。** 依赖进程追踪的工具会被拒，换走附加接口的命令。
3. **数据库连的不是你以为的那台。** 服务和 MCP 可能连同网段的不同主机，以实连地址为准。
4. **链路会偶发彻底断掉。** 日志里有成批的连接超时，断的时候请求一直挂到连接超时，后台定时任务受害最重。

## 换个项目怎么复用

可以照搬的做法：

- 把「慢」拆成几层，每层写清证实和证伪的标准，先查最贵、最常见的。
- 用空查询量数据库往返：冷连接和热连接分开记，热连接约等于一次往返。
- 小响应、长首字节时间，直接指向服务端多趟往返。
- 结论分主因、放大器、已排除三档，每条带证据。
- 只诊断不落地，建议交给各自的流程。
- 共享机上按监听端口定位进程（进程身份校验）。
- 机器侧采集写成脚本，脚本调不到的另走一路，不硬塞。

要按项目重写的：四层的取证命令、判定阈值、进程定位方式、日志格式、前端测量手段。
