# 计划文档开头先讲大白话

## 要怎么做

- 每份计划文档，开头先放一节「先用大白话说清楚」，讲五件事：
  1. 要做什么；
  2. 为什么做；
  3. 做出来是什么；
  4. 怎么判断有没有用；
  5. 会不会动到什么。
- 这一节不用表名、类名和缩写，一般读者读完就知道这份计划在干嘛。
- 这一节控制在一屏内。
- 之后再写背景（Context）、设计、步骤、风险。风险评估和「为什么这么改、带来什么好处」照旧放在后面，写法见[方案必附风险评估](方案必附风险评估.md)和[优化文档写清为什么改和带来什么好处](优化文档写清为什么改和带来什么好处.md)。

## 为什么

2026-11-13，agent 交来一份计划，开头直接是背景和摸底表。我在批准计划那一步（Claude Code 计划模式的退出确认）把它驳回了，原话：「每次生成计划文档时候，能不能开头大白话说明主要内容」。

这和[技术文档先讲清是什么](技术文档先讲清是什么.md)是一类要求：先让人读懂，再给细节。

依据类型：本人纠正（2026-11-13）。

## 什么时候适用，什么时候不适用

- 适用：所有计划文档，计划模式里写的和手写的都算。

## 例子

- 不合格：计划第一节就是背景，接着一张摸底表，满是表名和缩写。
- 合格：第一节五条大白话，一屏读完；第二节起才是背景、设计、步骤、风险。
