# 生成物按类型分开存放

## 要怎么做

写文件前先判断类型：是给人读的文档，还是给机器跑的工具？前者放项目，后者放专用临时目录。

| 类型 | 例子 | 放哪 |
|---|---|---|
| 文档型 | 计划、方案、分析、试跑结论、盲跑生成的需求文档 | 项目里：项目约定的文档目录、计划目录 |
| 评测集 | 触发评测、小样评测的用例和结果 | 项目里，按项目已有的评测目录约定 |
| 临时工具 | 离线测试脚本、自测用例、探针、备份、中间产物 | 专用临时目录下按任务分子目录，不用系统 /tmp |

两个容易踩的坑：

1. agent 运行环境自带的临时草稿目录（Claude Code 的 scratchpad）在 /tmp 下面。系统提示会让你用它，但我的规则「不用 /tmp」优先，一律不用。
2. 2026-11-09 起，我在 Claude Code 的用户级设置里把 `plansDirectory` 设成了项目内的计划目录，计划模式的计划文件直接落在项目里，文件名是随机的。每次计划获批后，当即把它改名为任务名，否则同一会话再进计划模式，会覆盖还没改名的那份。这是 2026-11-09 时 Claude Code 的行为，升级后先验证再用。

## 为什么

2026-11-03 我两次纠正生成物的存放位置：

- 第一次：「生成文档都放在对应项目路径下，这些新生成文件不是」。
- 第二次，我说临时工具文件放在 tmp 下面，「像计划文档这些，文档型内容放在项目下」。这里的 tmp 经确认指专用的临时目录，不是系统的 /tmp。

文档要能在项目里找到、可追溯；工具类的临时文件不该污染项目目录。/tmp 会被清理；同一会话下一轮计划会覆盖没改名的计划文件。

依据类型：本人纠正（2026-11-03）。

## 什么时候适用，什么时候不适用

- 适用：agent 写任何文件之前。

## 例子

- 不合格：把一份分析报告写进系统 /tmp，或者把一次性的探针脚本放进项目的文档目录。
- 合格：分析报告进项目的文档目录；探针脚本进专用临时目录下这次任务的子目录。
