# 协作规矩索引

一行一条。新增规矩时在这里加一行，不加到[总索引](../INDEX.md)。已经装了用户级规则文件的环境，每条的一句话版本是常驻的，按名字直接读对应文件就行。

- [默认不派子代理铺开](默认不派子代理铺开.md) — 默认不派子代理、不跑多代理工作流；主会话单线加脚本，真要派先说清数量和成本、先只跑一个
- [方案必附风险评估](方案必附风险评估.md) — 凡是给方案，都要附风险评估：风险表、推荐和理由、本方案自身的风险和回滚；从真实生产环境的角度想
- [装外部组件前核对一手来源](装外部组件前核对一手来源.md) — 评估或引入外部 skill、库、依赖之前，先拿到原始文件逐字核对；网页摘要和聚合站的描述只当线索
- [技术文档先讲清是什么](技术文档先讲清是什么.md) — 写技术文档先讲清「这是个什么东西、怎么回事」，再进技术细节；涉及读者未必熟的概念时，开篇补一章原理并配图解
- [优化文档写清为什么改和带来什么好处](优化文档写清为什么改和带来什么好处.md) — 写优化、改造类文档必加一节「为什么这么改、带来什么好处」，六项写全，好处用同一输入的改前改后对照
- [能用脚本就用脚本](能用脚本就用脚本.md) — 能用脚本做的优先写脚本；模型只做需要读懂意思和取舍的事，不抄写、不搬运、不计数、不排版；篇幅上限写进检查脚本
- [先计划再做最小样品](先计划再做最小样品.md) — 要铺开到很多对象的工作和新工具的想法，问一轮就写计划、只做一个最小样品交我验收；不连续弹多题定范围（我要求逐轮追问时除外）；样品验收前不往配套工具上投入
- [先量产出再设必做步骤](先量产出再设必做步骤.md) — 给流程或提示词加「必查某类资料」之前，先用一两条只读命令数一数有多少、能命中几条；共用的一小堆资料由主会话扫一次
- [计划文档开头先讲大白话](计划文档开头先讲大白话.md) — 每份计划文档开头先放一节「先用大白话说清楚」，讲要做什么、为什么、做出来是什么、怎么判断有没有用、会不会动到什么，再写背景和技术细节
- [页面和图只按桌面全屏检查](页面和图只按桌面全屏检查.md) — 检查图和 HTML 文档页面时浏览器按桌面全屏（1920×1080），版面只适配全屏，不测窄屏和手机宽度；宽图允许在图框内左右滑
- [画图不为通过校验而删内容](画图不为通过校验而删内容.md) — 画图时不为通过校验或防溢出而删节点、删连线、合并泳道；遇到布局问题只改几何不改语义，宁可接受纵向滚动
- [生成的网页在本地留一份](生成的网页在本地留一份.md) — 用 Claude 的 Artifacts 生成的 HTML 都在本地留一份；文档里的链接指向本地文件，不拿需要登录才能看的私有链接当主链接
- [生成物按类型分开存放](生成物按类型分开存放.md) — 生成物按类型分开放：给人读的文档放项目里，临时工具放专用临时目录、不放系统 /tmp；计划模式的计划文件获批后立刻改名
- [执行命令前先用中文说明](执行命令前先用中文说明.md) — 执行命令前，先在正文里用中文说明它做什么、关键参数和副作用，再执行；有副作用的讲清影响范围
- [装软件类任务不要提问打断](装软件类任务不要提问打断.md) — 装软件、搭环境这类有合理默认值的任务，不弹选择题，自己选默认值并在方案或收尾里一句话说明
- [让分析原因时只给诊断，不改代码](让分析原因时只给诊断不改代码.md) — 我贴来生产异常、只说「分析原因」时，交一份诊断：根因排序、验证命令、按改动从小到大排的方案、一句话结论；不自己动手改代码和配置
- [开工画草图，收尾画定稿](开工画草图收尾画定稿.md) — 新功能开工先画草图捋业务、定思路，收尾画三张对齐真实代码的定稿图做复盘；小改动免图
- [学开源项目只讲思路不讲语法](学开源项目只讲思路不讲语法.md) — 我学开源项目时不亲手敲命令，由 agent 跑；只讲思路、策略、原理，不讲语法；每课一个设计问题，先让我猜再揭晓，原则由我定稿
- [共享机上起服务前先查端口](共享机上起服务前先查端口.md) — 在多人共用的机器上起无头 Chrome 或任何要监听端口的服务前，先查端口占用；起完、连上去之前再核实监听进程是不是自己的
- [最小测试先行](最小测试先行.md) — 验证每个模块或接口先做最小测试，按档推进，上一档不绿不进下一档；所有子路径都绿了才跑一次全量
- [汇报改动时写清楚改了哪里，链接要能点开](汇报改动时写清楚改了哪里链接要能点开.md) — 回复里提到的每个新建或改动的文件，一行一个能点开的链接加一句改了什么；说「改了 N 处」要列出是哪几处；工作区外的文件按编辑器约定写相对路径，旁边附完整路径兜底；回复里不出现没解释过的内部编号
