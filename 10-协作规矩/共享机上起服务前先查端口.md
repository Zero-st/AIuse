# 共享机上起服务前先查端口

## 要怎么做

起无头 Chrome（`google-chrome --headless=new`），或者任何要监听端口的本地服务之前：

1. 起之前查占用，命中就换端口：

   ```bash
   ss -ltn | grep -q ":<port> " && echo "被占，换端口"
   ```

2. 起之后、连上去之前，核实监听这个端口的进程属主。`ss -ltnp` 常常看不到别人进程的属主，要走 `/proc`：

   ```bash
   for d in /proc/[0-9]*; do p=${d#/proc/}; [ "$p" = "$$" ] && continue
     cl=$(tr '\0' ' ' < "$d/cmdline" 2>/dev/null) || continue
     case "$cl" in *remote-debugging-port=<port>*) echo "PID=$p owner=$(stat -c %U "$d")";; esac
   done
   ```

   这段循环按 Chrome 的启动参数匹配；起别的服务时，把匹配串换成它启动命令里带端口号的那一段。

   属主不是自己（`id -un` 的结果），就停手换端口，别继续连。两步都做完，才能发 CDP 指令。

3. 认错了人，只还原现场，绝不结束别人的进程。别人的进程一律不动，把误改的状态（比如导航过的标签页）恢复原样即可。
4. 起 Chrome 必须带 `--remote-allow-origins='*'`，否则 Python 一侧的 websocket 握手会直接返回 403 Forbidden。这是 2026-09-24 实测的行为，升级后先验证再用。
5. 临时的浏览器配置目录放在专用临时目录下这次任务的子目录里，不用 /tmp。收尾时按数字进程号结束自己的进程（绝不用 `pkill -f`，它会匹配到自己的 shell），再删掉这个目录。

## 为什么

2026-09-24 我明确要求：「下次起无头 Chrome，一定要先查端口占用」。

起因是那天用浏览器真机走查一个页面时，agent 直接用 9333 端口起无头实例，没查占用。9333 早被另一个用户的 Chrome 占着。agent 的实例绑不上端口，但进程照样起来了，不报错。于是 `curl http://127.0.0.1:9333/json` 返回 200，`/json/version` 也正常，看起来一切就绪，实际连的是别人的浏览器。agent 在别人的会话里跑完了整套点击测试，还把对方一个空白的新标签页导航到了我们的页面。

事后遍历 `/proc/*/cmdline` 加 `stat -c %U` 才认出属主。agent 把那个标签页还原成 `chrome://newtab/`，只还原，没有结束对方的任何进程；换到空闲的 9741 端口重做，结果才算数。

教训：原来的规矩只写了「别杀别人的进程」，没覆盖「别占别人的端口」。后者更隐蔽，因为它不报错，只是静默地驱动了错误的浏览器。在多用户共享的机器上，端口能连通，不等于是自己的实例。

依据类型：事故复盘（2026-09-24）；本人要求（2026-09-24）；本人要求（2026-11-24，补别的服务怎么核属主）。

## 什么时候适用，什么时候不适用

- 适用：在多人共用的机器上，起无头 Chrome 或任何要监听端口的本地服务。

## 例子

- 不合格：直接用一个常用端口起无头 Chrome，看到 `/json` 返回 200 就开始发指令。
- 合格：先查端口空闲；起完遍历进程，确认属主是自己，再连上去。
