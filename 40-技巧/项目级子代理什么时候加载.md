# 项目级子代理什么时候加载

**做法**：

- 会话进行中新建或修改了项目级自定义子代理（Claude Code 项目设置目录下的 `agents/<name>.md`），要重开会话才能按名字派发。
- 会话内想立刻试一个新子代理：把它的 system prompt 内联传给 general-purpose 或 Explore 跑（行为等价），确认逻辑后再重开会话，用 `subagent_type` 正式调用。
- 教别人写子代理、要让对方跑自定义子代理时，提前提醒这一条，免得被 not found 卡住。

**为什么**：做一次多代理入门练习时实测：项目级自定义子代理是在 Claude Code 会话启动时加载的。会话进行中新建或修改的子代理文件不会立即注册，用 Task 工具按 `subagent_type` 名字派发会报 `Agent type 'xxx' not found`。当时可用的内置类型只有 claude / claude-code-guide / Explore / general-purpose / Plan / statusline-setup。

配置的加载时机决定「改了能不能立刻生效」，这是 agent 工程里一条通用的知识。

实测环境：原文没有记录实测版本，也没有写日期；记录文件最后修改于 2026-06-08。升级后先验证再用。

依据类型：真实运行（实测，日期未记录）。

**什么时候用，什么时候不用**：

- 用：会话中刚写好或改了一个项目级子代理，马上就想用。
- 不用：原文没有记录。
