# 开大任务的提示词：六格骨架和过程中的四句话

预算怎么估见[用量怎么量、预算怎么写](用量怎么量、预算怎么写.md)；要不要派子代理见[默认不派子代理铺开](../10-协作规矩/默认不派子代理铺开.md)；先做试点见[先计划再做最小样品](../10-协作规矩/先计划再做最小样品.md)。这条讲第一条提示词怎么写全、过程中怎么说。

**做法**：

开场按六格写，已经想好的哪怕只有两三条也写上：

| 格 | 写什么 | 不写会怎样 |
|---|---|---|
| 目标与读者 | 做什么、给谁用 | AI 会先问一轮 |
| 成品长什么样 | 形态、在哪看、大概多长 | AI 按自己的想象做，做完再改 |
| 硬约束 | 已经想好的要求 | 做完才发现不对，返工 |
| 做法 | 先试点；能脚本就脚本；要不要子代理 | AI 默认往「查全、并行」的方向走 |
| 预算与止损 | 上限多少，超了怎么办 | 没有上限，它不会自己停 |
| 这一轮停在哪 | 做到哪一步交给你看 | 它会顺手往下做 |

过程中的四句话：

| 场景 | 别这么说 | 这么说 |
|---|---|---|
| 让 AI 提改进 | 「其余你来补充完善」 | 「最多提 5 条，按回报排序，每条写清成本，我来勾选做哪些」 |
| 让 AI 复查 | 「看看还有没有要优化的」 | 「从业务内容的角度复查，不看版式；只列问题，先不动手」 |
| 中途换方向 | 直接打断，说新任务 | 「停下当前的。改做 X，范围是 A、B、C，先只做 A 一个，量出成本再说」 |
| 批准计划前 | 直接批准 | 「这个估算的依据是什么？有没有同类的实测数字？」 |

还有三个写法习惯要避开：

- 开放式委托。「其余你来补充完善」「看看还有没有要优化的」这类话，AI 每次都会多做一圈，做出来的东西没有一样是你点过头的。
- 一轮里连续打断、改方向。前面做到一半的东西基本作废。
- 批准计划只看结论，不问估算的依据。

已经写进 agent 规则文件或记忆的约束，开场不用再写，提示词可以很短：继续哪件事、先读哪个看板、本会话只做什么、预算多少、做完停下报用量。

**为什么**：

2026-11-12，一次两天的文档会话结束后，AI 对我的提示词做了复盘。下面是复盘的结论，不是我的原话：每条要求本身都对，问题在时机，最关键的几条约束都是在 AI 已经走错之后才出现的。

| 要求 | 什么时候才说 | 晚到的代价 |
|---|---|---|
| 读者是谁、成品是图文网页加术语表 | 第 2 轮（第 1 轮只有一句「整理出业务文档库」） | AI 先弹了一轮问答，还想再弹三题 |
| 先写计划，只做一篇试点，由我验收 | 第 3 轮，在拒绝了那三题之后 | 一轮来回 |
| 术语表做成公共模块 | 试点做完之后 | 术语表先写进单篇，再抽出来、再迁移 |
| 只适配全屏 | 试点做完之后 | 白做了 390、500、554、1440 几档窄屏测量 |
| 复查要看业务内容，不只看页面结构 | 复查做到一半时打断 | 前半轮查的结构项不是我最关心的 |
| 并行做 3 个模块（没点名是哪 3 个，没给预算） | 同一轮里第二次打断 | 模块由 AI 挑；它估 380 万我照批，工作流自己报的一段就是 510 万，按会话记录实测还要大得多 |
| 能脚本就脚本，划清模型和脚本的边界 | 最后才说 | 放在开头的话，手写网页、手抄行号、子代理取证这三件事都不会发生 |
| token 预算和止损 | 始终没说，直到被限额 | 被限额；工作流自报 510 万，实测更多，见[用量怎么量、预算怎么写](用量怎么量、预算怎么写.md) |

复盘也记了做得好、建议保留的：要求先计划后试点；指着具体一步问「这一步是不是过于复杂了」，一问就中；发现超支立刻叫停；用计划模式卡关口。还写明了哪些不该由我来防：估算用错基准、没跑通一篇就三篇并行、让模型干搬运的活，这些是 AI 自己的问题。

骨架和四句话没有在同类大任务上做过前后对照，所以标「未验证」。

依据类型：事故复盘（2026-11-12 复盘）；使用统计（2026-11-12）。

**什么时候用，什么时候不用**：

- 用：要跑好几轮、要出一批成品、会花掉几十万 token 以上的任务。
- 不用：一问一答的小事；已经有固定流程、开场一句「继续」就够的任务。

**例子**：

虚构任务「给差旅报销系统写一套业务讲解」，开场这样写：

```text
目标：给差旅报销系统写一套业务讲解，读者是新来的开发同事。
成品：每块业务一篇图文网页，全库共用一份术语表；只在桌面全屏下看。
硬要求：
1. 先写计划，只做一篇试点（报销提交），停下等我验收。
2. 能用脚本做的不让模型做：枚举、统计、行号、排版、校验都写成脚本。
3. 术语表、样式、检查工具一开始就做成公共的。
4. 不派子代理；要派，先告诉我数量和估算。
预算：这一轮新增量不超过 30 万、轮数不超过 50；每做完一步自查用量，要超就停下告诉我。
验收我看三点：新人能不能说清这块业务；开发能不能按文中位置找到代码；一篇读完不超过 30 分钟。
这一轮停在：试点篇做完，给我验收表和实际用量。不顺手做别的模块。
```
