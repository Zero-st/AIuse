# 思维导图随阶段和关键决定更新

## 什么时候用

项目反复跨聊天接续，需要一眼看懂目标、各条主线到哪、哪些事已决定、下一步做什么。详细状态、理由与验收证据仍以原记录为准。

## 做法

1. **先找已有图。** 沿用同一文件和根主题，保持主分支稳定。主分支写目标、阶段或工作线，细节放到子节点或节点备注。
2. **让节点说明状态。** 用「已确定」「待讨论」「下一步」等词。想法和未验证推断保持待讨论，确认后再更新结论。会话里同时给一份短文字提纲，便于继续讨论。
3. **只在重要变化时更新。** 阶段、方向或重要决定发生变化，先更新原记录，再就地调整受影响的导图分支。普通进度优先留在原记录。
4. **更新后回读。** 核对根主题、主分支、受影响节点和状态，确认历史分支仍在。需要发给不同的工具时，可以按同一层级导出 Markdown 或 OPML。

## 例子与依据

一份路线导图用状态标记呈现各阶段，用独立分支放优先行动。2026-11-24 只读核对其 Markdown 和 OPML 版本，9 个主分支的名称和顺序一致。另一次项目联动的原记录记载，同一份 XMind 更新后回读保留了 6 个主分支、共 83 个节点，并有备份。

「已验证」限于结构对照和这次有记录的回读。导图是否让评审更快、交接更顺，需要实际使用反馈。

依据类型为真实运行（同一 XMind 更新后回读）和评测记录（2026-11-24，两种提纲格式结构对照）。
