# 用结束钩子做收尾门禁

**做法**：想让 agent 不可能带着红门禁结束一轮，用 Claude Code 的 command 类型 **Stop hook**：

- 门禁不过时，hook 输出 `{"decision":"block","reason":"..."}`。`reason` 会进入 Claude 的上下文，并且真的阻止回合结束，agent 会看到内容并继续修。
- **不需要** `continueOnBlock: true`。那个字段只出现在官方文档的 prompt hooks 章节，command hook 用不上。
- 防循环的字段名是 `stop_hook_active`，为真时立即 `exit 0`。平台另有兜底：连续 block 8 次强制放行，上限可以用 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` 调。
- 做「收尾校验」应该选 Stop，而不是 PostToolUse。`PostToolUse` 不能撤销已经发生的写入，只能反馈。
- 配置放项目的共享设置文件（进仓库，clone 下来就有）。本机私有的设置文件（settings.local）只放在本机，机器的绝对路径只能放在这里；并且要在仓库的 `.gitignore` 里兜一道，别只靠个人的全局 git 忽略规则，别人 clone 下来没有。

写 hook 时：

- 别凭文档推断 hook 的行为，先写一次性、会自己解除的探针实测：只有 armed 标记存在时才 block，block 后删掉标记，只响一次，不会把会话卡死。
- hook 里挑解释器要择优：`python` 可能不在 PATH，系统的 `python3` 可能没装 pytest。优先选能 `import pytest` 的那个，否则测试门每轮都是假红。
- 跑不起来时如实报红，别静默跳过。静默跳过就是假绿。
- 别做「临时关掉」的豁免开关，豁免会让门禁失效。要停就显式删配置。

**为什么**：这是把 CI 门禁前移到会话内的落地机制，让 agent 不可能带着红门禁结束一轮。它比「把规则写进文档让 AI 读」有效得多：在一个仓库里，同一条 emoji 规则写进 5 个文档、每次自动注入，仍然复发了 3 次。读到不等于遵守，机器拦才行。

官方文档对 command hook 的这些行为没写死，上面几条是用探针验的。

实测环境：2026-09-21。原文没有记录实测版本。升级后先验证再用。

依据类型：真实运行（2026-09-21 探针实测）；事故复盘（同一条规则写进 5 个文档仍复发 3 次）。

**什么时候用，什么时候不用**：

- 用：要保证每一轮结束前某项检查必须是绿的，比如测试必须通过、某条格式规则不能违反。
- 不用：原文没有记录。
