# 复审只看上一轮之后的改动

审查的整体做法见[审代码的方法：检查单分两层，定级带门禁，结论附证据](../30-方法思路/审代码的方法检查单分两层定级带门禁结论附证据.md)。这条只讲第二轮及以后的审查怎么做。

**做法**：

派活方附了上一轮报告（路径或正文），或者说明是复审、而且找得到上一轮报告时，审查代理做增量复审，不重新全审：

1. **先判断上一轮之后改了什么。** 对照上一轮报告的审查范围和行号，用文件修改时间和版本控制的改动对比，找出之后新改的文件或段落。什么都没改，就直接回报「上轮之后无改动，结论不变」，不再逐条复查。
2. **逐条核对上一轮的阻断和重要。** 每条给出三种结论之一：已修（附位置）、未修、改法引入了新问题。次要和建议只在对应代码被改动时顺带看。
3. **只审新改的部分和它的直接调用方。** 新改动命中哪类专项就只查那一类，不重跑整张检查单。
4. **报告在「审查范围」前加一行**：

   ```
   复审：上轮 Blocker a、重要 b → 已修 x、未修 y、新增 z
   ```

   首行的阻断数只算本轮仍存在的和新增的。

没附上一轮报告，或派活方明确要「终审」「全量审」时，按普通审查做，并在报告里注明。

**为什么**：

2026-11-04 加这条之前做过一次对照：用同一句提示「复审……，上一轮报告见……」，配一份上一轮报告的摘录当夹具，代码在两轮之间没改过。

| | 工具调用 | 耗时 | 新增 token | 报告 |
|---|---|---|---|---|
| 改前 | 51 次 | 6.6 分钟 | 约 17.3 万 | 代码没改，仍然全量重审 |
| 改后 | 8 次 | 1.3 分钟 | 约 3.5 万 | 带「复审：上轮 Blocker 0、重要 1 → 已修 0、未修 1、新增 0」，并写明判断依据和局限（只看了文件修改时间） |

工具调用少了 84%，耗时少了 80%。同一天的回归评测仍是 15 条断言全过。

局限：只在一个夹具上对照过一次。那个夹具依赖当时工作副本里还没提交的代码，没有放进回归评测，代码变了结论可能不同。真实使用中复审省了多少，没有统计。

依据类型：评测记录（2026-11-04 对照）；流程规范（2026-11-04）。

**什么时候用，什么时候不用**：

- 用：上一轮审查报了阻断或重要问题，修完再审。
- 不用：没有上一轮报告；或者要提交前的终审、全量审。

**例子**：

上一轮报了 1 条重要问题，开发者说修好了，只改了一个文件里的两段。复审代理先对比修改时间，确认只有这两段变了；核对那条重要问题，已修，附上位置；新改的两段命中「查询语句」专项，只查这一类，没发现新问题。报告首行 `Blocker 数：0`，正文第一行 `复审：上轮 Blocker 0、重要 1 → 已修 1、未修 0、新增 0`。
