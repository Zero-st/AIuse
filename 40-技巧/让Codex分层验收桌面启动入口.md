# 让 Codex 分层验收桌面启动入口

## 什么时候用

让 Codex 交付桌面快捷方式、启动器，或从图标打开本地服务时，用这套步骤验收。

## 做法

1. **自动化测试。** 跑启动逻辑和直接受影响的回归测试，记录命令、结果和覆盖场景。用模拟失败或模拟点击测到的行为，标为测试覆盖。
2. **真实入口冷启动。** 确认没有沿用已运行的服务，再用用户平常点击的图标启动。查看启动日志或发起健康检查，记录哪个信号表明本次启动的服务已经就绪。
3. **用户界面。** 确认目标页面实际显示了预期内容。若交付包含关闭窗口后重开或失败提示，分别执行相应操作，记录看到的页面和提示。无法观察的场景列为待验证，写清还差哪个操作或可见结果。

如果需求包含防重复启动，第一次启动仍在进行时，从同一桌面入口再点一次。对照启动记录和窗口变化，确认有没有启动第二个服务，以及是否弹出意外错误。按项目约定记录预期行为，例如忽略第二次点击或聚焦已打开的窗口。

下面这段话可以直接发给 Codex。

> 请分别验证自动化测试、从真实入口启动后服务是否就绪、用户实际看到的页面和交互。每层给出证据。如果要求防重复启动，从真实入口连续点击两次，记录是否重复启动、窗口怎么变化、有没有意外报错。窗口关闭后重开、真实失败提示等未实测的场景单列。

## 为什么

2026-11-09，在一个 Windows 本地网页工具的桌面快捷方式交付中，28 项定向测试通过。从真实快捷方式冷启动后，启动日志记录服务就绪，随后也确认服务在运行。页面内容、关闭窗口后重开和真实失败弹窗没有完成界面验收。

2026-11-24 补录时复跑了两项测试。模拟重复点击验证了启动器跳过第二次启动且未请求弹出错误提示，模拟启动失败验证了传给提示函数的内容。真实桌面连续点击和实际弹窗仍待验证。整套流程保留「未验证」，待验证部分集中在第三层。

依据类型为真实运行（2026-11-09，Windows 桌面冷启动）和评测记录（同日 28 项定向测试）。
