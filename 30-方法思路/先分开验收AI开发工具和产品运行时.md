# 先分开验收 AI 开发工具和产品运行时

## 什么时候用

团队已经用某个 AI 工具帮忙开发，又准备让产品后端调用同一个工具。两条路径面对的用户、权限和环境各有自己的要求。

## 做法

1. **开发侧看真实工作会话。** 在目标开发环境开一个新会话，核对项目指令、技能和钩子是否按预期加载、触发。文件存在和脚本测试通过可以作为这层的部分证据。
2. **产品侧从真实入口验证。** 按产品约定的身份、权限和运行环境，从网页或 API 发出一次真实请求。核对工具是否完成了指定任务、实际可用权限是否符合预期，以及取消、超时或失败时能否正确结束并告诉用户。
3. **按产品自身的证据放行。** 最小命令行调用用于排查启动和通信。产品入口、工具权限或退出行为还有缺口时，记录缺口并保持产品入口关闭，补齐证据后再判定是否放行。

## 例子与依据

2026-09-26，一次尝试把 Codex 接进本地网页产品时，记录中的 Codex CLI `0.147.0` 已能返回最小调用结果。产品侧预检中，实际网页读取失败，可用工具也超出了预期的隔离范围，所以当时维持产品入口禁用。

「已验证」指该案例实测出了命令行调用和产品预检的不同结果。真实产品端到端、开发会话的钩子触发以及升级后的行为，各自需要对应的运行证据。升级后先验证再用。

依据类型为评测记录（2026-09-26，最小调用与产品接入预检）。
