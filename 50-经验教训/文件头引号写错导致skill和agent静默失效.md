# 文件头引号写错导致 skill 和 agent 静默失效

**做法**：写或改 skill、agent 的说明文件时，文件头（YAML frontmatter）里的描述这样写：

- 描述的值一律用双引号包起来。里面有「冒号加空格」或井号的时候尤其要包。
- 双引号包住的串里面，不要再出现英文双引号。要引用别人的话，用「」。
- 描述里不用英文尖括号。要写占位符用花括号。
- 描述不超过 1024 个字符。
- 改完用校验工具验一遍文件头，比如公开的 skill-creator 自带的校验脚本 quick_validate。
- agent 改完之后，还要开一个新会话，确认它出现在可用的 agent 列表里。校验通过不等于加载成功。

**为什么**：出过两次事，方向正好相反。

第一次，2026-08-18 做全量检查，16 个 skill 里有 11 个不合规。它们的描述以一个带冒号的前缀开头，又没加引号，冒号加空格被 YAML 当成了嵌套的键值，严格解析会报错。当时的加载器比较宽松，这些 skill 一直能用，所以没人发现；但打包工具和校验工具会判失败。修法是给描述加上双引号，改后 16 个全部通过校验。

第二次，2026-11-03，后果更重。一个 agent 的描述加了双引号，串里面又嵌了一对英文双引号，YAML 在第二个引号处就把字符串截断了。结果是这个 agent 不加载，而且没有任何报错，只是从可用列表里消失。这是一次静默失败（silent failure）：断档 6 天没人察觉，期间 7 次派发都落空。

两次合起来的教训：不加引号时，宽松的加载器还能兜住；加了引号再嵌引号，就兜不住了。所以「加引号」和「串内不嵌引号」必须一起做。

依据类型：事故复盘（2026-08-18；2026-11-03）；评测记录（修复后 16 个全部通过文件头校验）。

**什么时候用，什么时候不用**：

- 用：新建或修改任何 skill、agent 的说明文件时。
- 不用：只改正文、不碰文件头时。

**例子**：

- 会出事：`description: "…用户说"某功能报错"时使用…"`，字符串在第二个双引号处被截断。
- 不出事：`description: "…用户说「某功能报错」时使用…"`。
