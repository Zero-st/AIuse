# 循环要有界、有门禁、过程落盘

**做法**：

- 「改到成功为止」的循环写死次数上限。当时试点的有界编译自愈循环是这样设计的：编译失败就把报错交给 agent「只修编译错」，再编译，最多 maxAttempts 次（默认 3）；超限，或者 agent 判定需要人，就停在门禁上，不重启、不提交、不部署。
- 循环的编排脚本先落盘，人审过再运行。
- 定时任务遇到跳过或前置条件不满足，要非零退出，或者让每日报告能统计到。原文的说法：「『跳过』不报错的定时任务等于没有」。
- 定时复盘的产出交人工采纳，不让它自动改能力。
- 用 cron 跑无头 `claude -p`、又要用经 `npx` 启动的 MCP 服务器时，wrapper 里先取到 nvm 管理的 node 的 bin 目录，再把它加进 PATH：`NVM_BIN=$(ls -d $HOME/.nvm/versions/node/*/bin|sort -V|tail -1)`。
- 创建和启用可写的无头 `claude -p` 定时任务，交用户亲手执行，见 [自动模式的分类器会拦什么](自动模式的分类器会拦什么.md)。

**为什么**：

2026-07-24，评估把 Claude Code 的循环能力（`/loop`、`/schedule`、`ScheduleWakeup`、Workflow 的 `loop-until`）接进一个项目。盘点发现，项目已经在「用循环思考」，但循环全靠文字约定，无界，也没有运行时约束：缺陷修复和需求开发两个编排流程，回退重做没有计数；一个批量改造的工作流脚本里有一句真正无界的「直到 BUILD SUCCESS」。由此定下，循环必须「有界 + 门禁(超限 fail-to-ask 交人工) + 落盘可审」。2026-10-28，两个编排流程的回环改成最多 2 轮。

2026-07-27，用 cron 跑无头 `claude -p` 时，经 `npx -y` 启动的数据库 MCP 一直停在「still connecting」。根因是 node 由 nvm 管理，不在 cron 的默认 PATH 里。在 wrapper 里把 nvm 的 node bin 加进 PATH 后，干净环境下的 `SELECT 1 FROM DUAL` 探针返回 `OK=1`。

2026-08-04，每周自进化复盘的周报里，自评价值最高的建议是把 3 个 skill 预载进开发 agent。人工审过之后只预载了 1 个：另两个里，一个是编排器，会反过来调开发 agent，形成循环；另一个需要开发 agent 没有的派子代理工具。原文把这件事叫作「周报建议须人工把关、不自动落地」的活标本。

2026-11-04 清点定时任务：每天抓 GitHub 热门仓库的那一条，从 2026-09-03 起 `gh` 就没登录，脚本跳过时仍然 exit 0，静默空转了 62 天没人发现。同一天退役的还有三样：试点的有界编译自愈循环，从未运行；每周自进化复盘的定时任务，改成手动触发的复盘命令；7×24 常驻的 agent 分身，8 月以来只完成 1 个任务。2026-11-09，每日用量报告我判断没起作用，也暂停了。

实测日期见上，原文没记 Claude Code、node 和 nvm 的版本。升级后先验证再用。

依据类型：评测记录（2026-07-24 盘点现有循环）；事故复盘（2026-07-27 无头 MCP 起不来；2026-11-04 定时任务静默空转 62 天）；迭代记录（2026-08-04 周报建议人工把关；2026-10-28 回环限 2 轮；2026-11-04 退役）。

**什么时候用，什么时候不用**：

- 用：让 agent 反复重试，直到某个条件成立；把 Claude 做成定时任务（系统 cron 加 `claude -p`）。
- 不用：原文没有记录。

**例子**：

- 不合格：工作流脚本里写「直到 BUILD SUCCESS」，没有次数上限。
- 合格：最多 3 次，超限停下交人，不重启、不提交、不部署。
- 不合格：定时任务发现 `gh` 没登录，跳过，然后 exit 0。
- 合格：同样的情况非零退出。
