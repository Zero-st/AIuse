# 离线验收要停后端整页重载

## 什么时候用

应用承诺联网用过之后可以离线访问，或刚改了缓存、路由、页面初始化。先核对测试装载的是哪个版本、已有缓存和首次访问各承诺什么，以及停掉的是本次可控制的服务。

## 做法

1. **在线准备。** 从真实使用入口打开一次，等当前 Service Worker 生效，验证预期缓存或最后成功数据已经写入。记下版本与基线。
2. **离线从零走启动路径。** 停止本次测试服务，或用隔离的离线环境，从目标路由整页重载。观察页面骨架、最近成功数据、提示和控制台。分别检查有缓存与无缓存的预期。
3. **用路由回归锁定故障。** 如果独立页面因另一个模块的请求失败而不渲染，先写能经过真实路由的断言复现。把独立页面初始化接回自己的数据入口，再重跑断言和整页重载。
4. **恢复服务后再刷新。** 核对缓存提示是否撤下，以及实际读取时间和原数据生成时间是否各自准确。

## 为什么与例子

2026-10-15，某应用进度页在线可见，停后端整页重载后变成空白。当时的视图切换只有在资讯请求成功后才触发渲染，已有的进度缓存因此用不上。实际路由回归先失败，进度和每日安排独立启动后通过。重新联网安装资产，再停后端重载，两个区域都显示缓存和时间。

依据类型为事故复盘、真实运行（当日停服务复现、修复和浏览器复验）和评测记录（路由回归红转绿，2026-11-24 在 Node.js v24.13.0 复跑通过）。本轮复跑使用隔离夹具。换浏览器、缓存策略或运行版本后先验证再用。
